# Pages with Drill-down (feature 16) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One model shown over several pages, with one threat register and one set of insights. Page tabs sit at the top-left of the canvas. A shape can link to a page that shows its detail. Deleting a page deletes its shapes, after a confirmation.

**Architecture:**
- **Separate areas:** each page has a horizontal `offset` (a multiple of `PAGE_STRIDE = 100000`), and its shapes are stored in that area of the shared coordinate space. An older version therefore shows pages side by side, and geometric trust-boundary analysis never mixes pages.
- **Showing a page:** the current page is "visible". `isItemVisible` (already used for hiding, selection, line jumps, the minimap and wire targets) also checks the page. The bounding box (used by zoom-to-fit, PNG, print and the minimap) covers only the current page. Switching page moves the view to the page's area.
- **New shapes:** they get the active page through `stampLayers()`. When their coordinates lie in another page's area (paste, Mermaid import), they are moved into the active page's area.

**Spec:** `docs/superpowers/specs/2026-11-09-diagramming-and-attack-paths-design.md` (section "16. Pages with drill-down"). User decisions: page tabs at the top-left; deleting a page deletes its shapes after a confirmation.

## Global Constraints

- **Default page:** `{ id: 'p1', name: 'Page 1', offset: 0 }`. Existing models load as one page, unchanged.
- **Limits:** at most 50 pages. Ids match `/^[\w-]{1,40}$/`. Names are text of at most 60 characters. An offset must be a finite number; an invalid or duplicate offset gets the next free multiple of `PAGE_STRIDE`.
- **Flows stay within one page.** A flow is on the page of its source. Moving shapes to another page is refused, with a notice, when a flow would connect two pages.
- **Analysis covers all pages:** the threat register, suggestions, model checks, insights and attack paths. The register shows the page next to the component name when there is more than one page. Jumping to a component switches to its page.
- **Exports:** PNG shows the current page. Mermaid export shows the current page. The Markdown report has one diagram per page. JSON contains everything. Print shows the current page's diagram (my call; see the ledger).
- **What is undoable:** page add, rename, delete and move-selection are one undo step each. Switching page is view state: it is saved as `activePageId`, with no undo step.
- Imported page data is untrusted, and the XSS suite gets a page name. No new unreviewed `innerHTML`. Sync, lint and the full suite stay green. CHANGELOG, README and Help are updated. No version bump, no push.

## Review Focus

1. **Old models:** a model with no `pages` field opens as one page and is byte-identical after a save round trip, apart from the added `pages` and `pageId` fields. Test in Task 1.
2. **Paste or import onto page 2:** copies land inside page 2's area, not in page 1's. Test in Task 2.
3. **Deleting the active page or the only page:** the only page cannot be deleted. Deleting the active page switches to a neighbouring page. Undo restores the page, its shapes and their threats. Test in Task 3.
4. **Moving shapes that would split a flow:** refused, with nothing changed. Test in Task 3.
5. **Links to a deleted page:** `linkedPageId` is dropped when the page is deleted (and on import when unknown), and the badge disappears. Test in Task 3.

---

### Task 1: Model, import, undo, export, stamping

- `PAGE_STRIDE`, `MAX_PAGES`, `normalizePages(raw, ctx)`.
- In `normalizeSession`: `pages`, `activePageId`, each element's `pageId` (unknown ones go to the first page) and `linkedPageId` (dropped when unknown).
- `ThreatModelSession` gets default `pages` and `activePageId`.
- `serializeModel` and the export payload include `pages`.
- `stampLayers()` also stamps `pageId` and moves new items into the active page's area.

Tests (`tests/pages.spec.js`):
- an old model gets one page;
- hostile pages (a script name, duplicates, bad ids, 80 pages, NaN offsets) load safely;
- an element on an unknown page goes to the first page, and an invalid `linkedPageId` is dropped;
- JSON round trip.

### Task 2: Showing a page, tabs, switching

- `onActivePage(item)`.
- `isItemVisible` and `indexLayers` include the page.
- `getIsometricBoundingBox` covers the current page only.
- `setActivePage(id)` remembers each page's pan and zoom; a page shown for the first time zooms to fit, or centres on its area when empty.
- `#page-tabs`: a strip at the canvas's top-left with a button per page (`role="tab"`, `aria-selected`), double-click to rename inline, a `+` button `#btn-page-add`, and a delete `×` on the active tab when there is more than one page.
- `focusCanvasItem` switches page.

Tests:
- shapes on another page are hidden;
- zoom-to-fit uses the current page;
- a new shape on page 2 has `pageId` p2 and an x inside page 2's area;
- paste and Mermaid import onto page 2 land in page 2's area;
- jumping to a component on another page switches page.

### Task 3: Delete, move, drill-down, register, exports, docs

- `deletePage(id)` asks through `confirmAction`, then deletes the page's shapes, the flows touching them and their threats. It is one undo step.
- `moveSelectionToPage(id)` shifts x by the offset difference and refuses when a flow would cross pages. It is offered as a "Move selection to page" `<select>` in the strip.
- Drill-down:
  - Properties for a model node get a "Detail page" `<select>` (`#props-linked-page`).
  - A badge `.page-link-badge` on the node opens the linked page.
  - A "◀ Back" button in the strip returns to the previous page.
- The register shows the page name when there is more than one page.
- `buildMermaidDiagram({ pageId })` covers one page; the Markdown report has one diagram per page.
- Docs: Help, README, CHANGELOG.

Tests:
- delete with confirmation, then undo;
- the only page cannot be deleted;
- a move is refused when a flow would cross pages, and works otherwise;
- linking a page, clicking the badge and going back; the link is dropped when its page is deleted;
- the register label;
- one Markdown diagram per page.
